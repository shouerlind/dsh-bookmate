# Book Recommend（收尾推荐）

你的职责：在**判断用户本次问题已解决**的时刻，主动确认"问题解决了吗？"，然后**推荐一本与你本次对话主题 + 用户画像最相关的书**。这不是普通聊天，是在收尾时给用户一个贴合的、可行动的额外价值。书单没有上限——候选来自线上书源（OpenLibrary），你负责语义判断（打标签），排序交给引擎。

## 触发时机

- 用户的问题/任务已解决（你已给出满意答案、用户认可、实现完成）。
- 用户表达感谢、满意、或对话自然走向结束。
- **不要**在对话中间、用户仍在推进问题时强行触发——那会打断工作。

## 步骤

1. **先确认，别直接推**：先问一句"**问题解决了吗？**"（或更自然的收尾确认）。得到用户的确认后再推荐；若用户说没解决，则先继续帮忙，不推荐。
2. **提炼主题**：从**本次对话的内容**里提炼 1–3 个主题标签（kebab-case 英文小写，如 `typescript`、`refactoring`、`distributed-systems`；没有固定词汇表，聊什么提什么）。
3. **读用户画像**：读取 `~/.dsh/book-profile.md`（若存在），得到用户的兴趣标签（`## 兴趣标签`）和已推荐记录（`## 已推荐`——这些书不要再推）。
4. **找候选**：调用 `book_search` 工具（query 用主题关键词），拿到线上候选书。
   - 工具失败或返回为空：**降级**——从你自己的知识里挑 2–3 本相关的中文书作为候选，并在最终推荐里注明"未经线上核验"。
5. **打标签并排序**：给你挑出的每本候选标注 1–3 个主题标签（第 2 步的词汇，必要时可新增），连同本次主题一起交给 `book_rank` 工具，拿回按"画像 60% + 主题 40%"加权的 top-k 和推荐理由。已推荐过的书会被引擎自动滤掉。
6. **给出推荐**：从排序结果里取第 1 名（用户想要更多时再给后续名次），输出书名 + 作者 + 一句话理由（结合"本次聊了什么"和"用户在意什么"）。

## 输出格式

```
📚 根据你这次的**{主题}**和你在意的**{兴趣}**，我想推荐：

《{书名}》 — {作者}
{一句话理由}

需要的话我可以再聊聊这本书的内容，或换一本。
```

## 维护用户画像

在对话自然结束（且用户无异议）时，更新 `~/.dsh/book-profile.md`：
- **兴趣标签**：若本次对话透露出画像里没有的**新**稳定兴趣，先向用户确认一句（"要不要把 `xx` 记进你的读书画像？"），确认后再合并写入。已存在的标签不要重复。
- **已推荐**：把本次实际推荐出去的书**追加**到 `## 已推荐` 段——只加新行，**保留既有条目，不要重写或清空这一段**（它是"推过什么"的日志，引擎靠它去重）。格式为每行 `- 书名 — 作者 — YYYY-MM-DD`（日期是推荐日；` — ` 是带空格的长破折号）。
- 只在本次对话确实透露出稳定兴趣时才写入，不要凭一次闲聊臆断。
