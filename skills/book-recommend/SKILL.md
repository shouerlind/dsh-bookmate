# Book Recommend（收尾推荐）

你的职责：在**对话走到尾段**的时刻，判断该不该推荐，并在合适时推荐一本与本次对话主题 + 用户画像最相关、且能直接点开的书。这不是普通聊天，是在收尾时给用户一个贴合、可行动的额外价值。候选来自线上书源（OpenLibrary），你负责语义判断（打标签），排序交给引擎；引擎会滤掉已推荐过的书，并把书页链接/封面一并带回。

## 触发分级（先看信号，别一刀切）

先归入下面三档，再决定怎么做：

- **明确收尾/任务已确认完成** —— 用户道谢/道别/说「就这样」「下次聊」，或明确认可你的答案、实现、交付。→ **直接推荐，不必再问。**
- **进入尾声但结果未定** —— 对话在收尾，但你还不敢确定问题解决了。→ **先问一句「问题解决了吗？」**，确认后再推荐；若用户说没解决或还要继续，先帮忙，不推荐。
- **对话仍在推进** —— 用户还在追问/迭代，或你还没给出结论。→ **绝不触发**，不要打断工作。

> 用户也可以**主动触发**：随时输入 `/book-recommend`（或简写 `/推荐`）来要一本，不必等自动收尾。

## 步骤

1. **判信号，定档**：按上面的「触发分级」归入三档之一。属于「仍在推进」就直接跳过。
2. **提炼主题**：从**本次对话的内容**里提炼 1–3 个主题标签（kebab-case 英文小写，如 `typescript`、`refactoring`、`distributed-systems`；没有固定词汇表，聊什么提什么）。
3. **读用户画像**：读取 `~/.dsh/book-profile.md`（若存在），得到用户的兴趣标签（`## 兴趣标签`）和已推荐记录（`## 已推荐`——这些书不要再推）。
4. **找候选**：调用 `book_search` 工具（query 用可搜索词）。**query 至少 3 个字符**——主题若是 2 字中文（如「重构」「算法」），OpenLibrary 会拒绝，请改用更长的中文短语、书名片段或英文关键词（如「重构」→「refactoring」）。拿到线上候选书（含书页链接 `url` 与封面 `cover`，同一本书跨版本已合并）。
   - 工具失败或返回为空：**降级**——从你自己的知识里挑 2–3 本相关的中文书作为候选，并在最终推荐里注明「未经线上核验」。
5. **打标签并排序**：给你挑出的每本候选标注 1–3 个主题标签（第 2 步的词汇，必要时可新增），连同本次主题一起交给 `book_rank` 工具（把该候选的 `url`/`cover` 一并带上），拿回按「画像 60% + 主题 40%」加权的 top-k、推荐理由、以及书页链接/封面。已推荐过的书会被引擎自动滤掉。
6. **给出推荐**：从排序结果里取第 1 名（用户想要更多时再给后续名次），输出书名 + 作者 + 一句话理由（结合「本次聊了什么」和「用户在意什么」），并带上书页链接（有封面则一并带上）。

## 输出格式

```
📚 根据你这次的**{主题}**和你在意的**{兴趣}**，我想推荐：

《{书名}》 — {作者}
{一句话理由}

🔗 查看这本书：{url}
📖 封面：![封面]({cover})     （仅当有封面时写这一行；用 `![封面](url)` 这种 markdown 图片语法，客户端会渲染成图片）
（若来自模型知识兜底，注明「未经线上核验」）

需要的话我可以再聊聊这本书的内容，或换一本。
```

## 维护用户画像

在对话自然结束（且用户无异议）时，更新 `~/.dsh/book-profile.md`：
- **兴趣标签**：若本次对话透露出画像里没有的**新**稳定兴趣，先向用户确认一句（「要不要把 `xx` 记进你的读书画像？」），确认后再合并写入。已存在的标签不要重复。
- **已推荐**：把本次实际推荐出去的书**追加**到 `## 已推荐` 段——只加新行，**保留既有条目，不要重写或清空这一段**（它是「推过什么」的日志，引擎靠它去重）。格式为每行 `- 书名 — 作者 — YYYY-MM-DD`（日期是推荐日；` — ` 是带空格的长破折号）。
- 只在本次对话确实透露出稳定兴趣时才写入，不要凭一次闲聊臆断。
